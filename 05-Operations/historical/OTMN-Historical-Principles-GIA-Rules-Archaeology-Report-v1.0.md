# OTMN Historical Principles & GIA Rules — Archaeology Report v1.0

**Status:** Historical reference document  
**Purpose:** Preserve the evolution of OTMN operating principles and GIA rules without changing the current standards merely for historical completeness.

## 1. Purpose

This document records the archaeological review of OTMN principles, operating ideas, GIA rules, and recurring concepts developed during the early formation of the OTMN operating system.

The purpose is historical preservation and comparison:

- identify principles and rules developed during earlier OTMN work;
- determine whether they were subsequently promoted into GitHub standards;
- identify concepts that were consolidated into broader principles;
- distinguish current standards from ideas that remain experimental or historical;
- preserve the path by which the current operating model evolved.

This is **not** a new operating standard and does not override current OTMN or GIA documentation.

---

## 2. Archaeology Result

The review found that the major foundational OTMN principles and GIA rules developed during the early project history have largely been captured in the current GitHub operating documents.

Very little important appears to have been permanently lost.

Several earlier ideas were not copied word-for-word. Instead, they were consolidated into broader principles or rules. This is considered a positive sign of maturation rather than a documentation failure.

The current GitHub standards should therefore remain the authoritative source for current operation. This document preserves historical development and context.

## 4. GIA Rules — Historical Mapping

The current GIA Standard contains twelve rules. The original rules identified during the archaeology pass remain represented in the current standard.

### Rule 1 — Read before modifying

GIA must read the current version of an existing file before making a change.

**Historical result:** Captured in the current GIA Standard.

### Rule 2 — Minimal purposeful structure

Prefer a minimal structure that solves the demonstrated need rather than building speculative infrastructure.

**Historical result:** Captured in the current GIA Standard.

### Rule 3 — Respect requested scope

Execute the requested level of work without unnecessarily advancing beyond scope.

**Historical result:** Captured in the current GIA Standard.

### Rule 4 — Direct-to-main only when explicitly permitted

Low-risk, explicitly permitted operations may use direct-to-main; meaningful structural or public-facing changes should use the appropriate branch/PR workflow.

**Historical result:** Captured in the current GIA Standard.

### Rule 5 — Understand the organization's rules

GIA should not merely act as a faster pair of hands; it should understand and operate within OTMN's established rules.

**Historical result:** Captured in the current GIA Standard.

### Rule 6 — Preserve unrelated existing content

Targeted modifications should preserve unrelated content.

**Historical result:** Captured in the current GIA Standard.

### Rule 7 — Avoid unnecessary work

GIA should help avoid unnecessary work, rather than simply automate unnecessary work faster.

**Historical result:** Captured in the current GIA Standard.

### Rule 8 — Identify conflicts before acting

Established repository structure, rules, and authoritative information should be checked before proceeding when conflicts may exist.

**Historical result:** Added during maturation and now formalized.

### Rule 9 — Minimum necessary access

Use the minimum authoritative information and access necessary to complete the task; do not weaken boundaries for convenience.

**Historical result:** Added during maturation and now formalized.

### Rule 10 — Prefer immediate progress toward the current objective

When otherwise eligible choices remain, context should favor progress toward the current objective.

**Historical result:** Added during maturation and now formalized.

### Rule 11 — Do not manufacture certainty

When authoritative information cannot distinguish between candidates, GIA should report the uncertainty rather than invent a ranking or conclusion.

**Historical result:** Added during maturation and now formalized.

### Rule 12 — Capture broadly, promote selectively

Ideas may be captured broadly, but promotion into active work should remain selective.

**Historical result:** Added during maturation and now formalized; strongly connected to the current PM lifecycle and Cookie Jar research.

## 5. Related Operating Concepts Already Captured

Several concepts that appeared historically as separate ideas now exist as operational procedures or broader principles.

### OTMN Core Idea

OTMN is described as a network for developing good ideas into useful things. The concept emphasizes providing the foundation and connections for ideas to prove themselves and grow into useful outcomes.

**Archaeological result:** Current canonical concept documented in GitHub.

### OTMN Operating Cycle

The operating cycle has evolved into:

**Capture → Reconcile → Evaluate → Select → Authorize → Queue → Execute → Reconcile again**

**Archaeological result:** Current GitHub operating model; historical variations were consolidated into this form.

### START HERE / Where Do I Begin?

The procedure for identifying exactly one next action from current authoritative information is now documented as an operational procedure.

**Archaeological result:** Captured and operationalized.

### Evidence before escalation

The historical behavior of waiting for evidence before creating additional process, automation, taxonomy, or infrastructure is now primarily represented through the principle:

> **Let the next layer earn its way into existence.**

**Archaeological result:** Consolidated rather than retained as a separate principle.

## 6. Concepts Deliberately Not Promoted

The archaeology pass identified several concepts that remain active ideas but have not yet earned promotion into the formal standards.

### Observe → Think → Measure → Nurture

**Status:** Validation mode.

This four-word OTMN formulation appears to describe a useful operating loop, but it is currently being tested through real OTMN observations rather than adopted as a formal principle.

**Decision:** Do not add to the formal OTMN Principles yet.

### Cookie Jar / Leave an Idea, Take an Idea

**Status:** Experiment stage.

Research supports the underlying mechanisms of idea commons, open-source contribution, discovery, low-friction participation, attribution, development, and return. The OTMN implementation remains an experiment.

**Decision:** Do not add to formal principles or standards yet.

## 7. Important Archaeological Finding

The strongest finding is not that every historical phrase survived.

It is that the **behavior survived**.

Repeated operating behavior was progressively consolidated into:

- OTMN Operating Principles;
- GIA Rules;
- the PM lifecycle;
- START HERE procedures;
- measurement and reconciliation practices.

This indicates that the OTMN operating system is evolving through repeated use rather than through speculative documentation alone.

That is consistent with the current OTMN principle:

> **Let the next layer earn its way into existence.**

## 8. Authority and Use

This report is historical reference material.

For current operation, use the authoritative GitHub standards and procedures rather than this archaeology report.

This document should be updated only when a meaningful historical discovery warrants preservation. It should **not** become a second copy of the current standards.

The intended distinction is:

**Current standards = how OTMN operates now.**  
**Archaeology report = how OTMN got here.**
